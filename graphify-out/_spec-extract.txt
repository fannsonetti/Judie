# SETTINGS GESTURE

Settings must NOT open using a conventional settings button.

Settings are accessed using a pull-down gesture.

Only the RIGHTMOST ONE THIRD of the top edge should activate this gesture.

Interaction:

1. User touches/drags downward from the top-right third of the display.
2. The settings interface physically follows the finger downward.
3. Movement must remain 1:1 and smooth while dragging.
4. Releasing after dragging sufficiently far opens Settings.
5. Releasing before the threshold smoothly retracts it.
6. Dragging the Settings sheet upward should dismiss it.
7. It must never teleport between states.

The left two-thirds of the top edge must NOT trigger Settings.

The network icon remains located inside this top-right region but should still respond normally to a direct tap.

Settings should behave like a native pull-down OS sheet rather than opening another webpage.

# WIDGET EDIT MODE

The widget system needs substantial interaction improvements.

## Grid

Widgets still ultimately live on the existing invisible grid.

Do NOT remove grid alignment.

However, dragging must become completely smooth.

Current behavior where widgets snap around while actively being dragged is wrong.

Correct behavior:

1. Widget follows the pointer/finger freely while dragging.
2. Do not constantly snap its visible position to grid cells during the drag.
3. Determine the closest valid grid position in the background.
4. On release, smoothly animate the widget into the nearest valid grid position.
5. The widget must glide into place.
6. It must never instantly teleport.

The interaction should feel similar to moving apps/widgets in iOS.

Grid collision rules should still prevent invalid overlap.

## Widget Size Label

Do NOT display things like:

* 1×1
* 2×1
* 2×2

in the upper-left corner of placed widgets.

Remove those labels completely.

## Delete Widget Control

In edit mode, the delete control must be exactly:

Place it at the widget's upper-right edge.

It should overlap the border similar to iOS edit controls rather than sitting completely inside the widget.

Do not enlarge it unnecessarily.

# UNINSTALL

Uninstall is deliberately difficult.

It should require THREE escalating confirmation stages.

## Confirmation 1

Simple confirmation:

"Are you sure?"

The user explicitly chooses to continue.

## Confirmation 2 — Math

Display a randomly generated equation using single-digit numbers.

Format:

`x + y × z`

Example:

`4 + 3 × 7`

Follow normal mathematical order of operations.

The answer in that example would therefore be:

`25`

not:

`49`

Generate new single-digit values rather than hard-coding the example.

Require the correct answer before continuing.

## Confirmation 3 — Verification String

Generate and display a random verification string.

It must contain a mixture of:

* lowercase letters
* uppercase letters
* numbers
* special characters

The user must type the string exactly.

Example style only:

`dK7@q2P!x`

Do not permanently use that exact string.

The verification string must be fully typeable using the custom on-screen keyboard.

If the user enters it incorrectly, do not uninstall.

Only after all three stages should uninstall actually become possible.

These confirmations should be presented cleanly rather than as browser `confirm()` dialogs.

Build proper interface modals/sheets matching the rest of the UI.

# MOTION AND TOUCH INTERACTION

This is a touchscreen-oriented interface.

Motion quality matters.

Use continuous finger tracking for:

* dragging widgets
* opening Settings
* closing Settings
* widget-size carousel swiping
* other swipe interactions

Avoid interactions where the element remains stationary while dragging and suddenly jumps after release.

Use appropriate easing only AFTER the user's finger/pointer has been released.

During active dragging, movement should track the pointer directly rather than easing behind it.

Use momentum/inertia only where it makes sense.

Do not make animations excessively long or flashy.

The desired feeling is:

* immediate
* physical
* controlled
* smooth

not decorative.
